# User Personas — AI Workshop

## Persona 1: 开发者 (Developer)
- **角色**: PR 作者 / Issue 提交者
- **特征**: 日常提交代码、创建 PR、报告 Issue 的工程师
- **目标**: 快速获得 PR Review 反馈，Issue 得到及时响应
- **痛点**: 等待人工 Review 耗时长，Issue 回复不及时
- **相关故事**: US-01, US-02, US-03, US-04, US-05

## Persona 2: 团队管理者 (Team Lead)
- **角色**: 工程团队负责人
- **特征**: 关注团队效率、Issue 分类、风险识别
- **目标**: 了解 Issue 分布、PR 质量趋势，减少人工分拣成本
- **痛点**: Issue 分类靠人工，缺乏自动化的风险提醒
- **相关故事**: US-06, US-07, US-08, US-12, US-13

## Persona 3: 系统管理员 (Admin)
- **角色**: 平台运维 / 配置管理者
- **特征**: 负责部署、配置规则、监控审计日志
- **目标**: 确保系统稳定运行，规则可灵活调整，操作可追溯
- **痛点**: 规则修改需要改代码重新部署，审计信息分散
- **相关故事**: US-09, US-10, US-11, US-14, US-15

## Persona 4: 外部贡献者 (External Contributor)
- **角色**: 开源社区贡献者
- **特征**: 偶尔提交 PR 或 Issue，不熟悉项目内部流程
- **目标**: 提交的 PR/Issue 能得到快速、友好的反馈
- **痛点**: 不确定 Issue 是否被关注，PR 长时间无人 Review
- **相关故事**: US-01, US-03, US-04
